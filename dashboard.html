A self-hosted dashboard builder running on the same GCP VM. Upload a spreadsheet, pick the columns, and the app turns them into interactive charts. try it →

  • FastAPI REST API, server-side sessions
  • React 19 Vite, TanStack Query, Zustand
  • ECharts 6 bar, line, scatter, KPI, table
  • DuckDB + PyArrow queries over Parquet
  • Messy spreadsheets header sniffing, type inference
  • Drag & resize grid react-grid-layout, saved layouts
  • SQLite metadata, sessions, audit log
  • Docker API + nginx, named volume
  • Caddy auto HTTPS, basic auth, reverse proxy
  • GitHub Actions build gate + SSH deploy
  • Puppeteer tests real browser, real charts
  • Tenant isolation every query scoped to a workspace

how it works

  • Upload — the workbook is sniffed for sheets, header rows and column types; the user confirms what to import, then the sheet is stored as Parquet.
  • Build — a widget is a dataset, a sheet, a chart type and a set of axes. The API validates every widget against the sheet's schema and refuses a dashboard that cannot render.
  • Query — each widget runs its own DuckDB query, so changing one chart does not refetch the whole dashboard.
  • Arrange — the canvas is a drag-and-resize grid; positions and sizes are saved with the dashboard document.

deployment

  • The VM runs the API and the built frontend as two containers; nginx serves the SPA and proxies /api to the API on the internal network.
  • Caddy terminates TLS and reverse-proxies dashboard.fahmykamal.site to it. The site sits behind a password, because the API's sign-up is open.
  • Metadata and sessions live in SQLite on a named volume, so a redeploy keeps every dashboard.
  • Pushes to main run CI (compose validate + image build), then deploy over SSH only after the build passes.
